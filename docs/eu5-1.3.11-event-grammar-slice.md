## 设计与验收标准

1. `EVENTS` 文件根必须先声明标识符 `namespace`，后续事件 ID 必须匹配
   `<namespace>.<1..9999>`。目前只覆盖 `type = country_event`；其他事件
   scope 明确报 out-of-slice，而不冒充通过。事件头部的 `option`、`outcome`、
   `orphan` 等是结构词；重复 option 不触发 root duplicate 检查。
2. 只对 EU5 exact-build profile 接受规范的 `location:<id>` 和 `c:<tag>`
   左值 scope 块，并继续递归验证其内部操作；其他 profile 不受影响。
3. 将夹具实际使用且有 exact-build 原版依据的 trigger/effect 登记为类型化
   opcode；建国与建筑国家的混合参数/效果块必须递归，不能把整块视为
   不透明参数而掩盖内部未知操作。
4. event `trigger` 为 trigger-side，`option` / `immediate` / `after` 中动作
   为 effect-side，option 内 `trigger` 可切回 trigger-side；`UNKNOWN_OPCODE`
   对未登记操作继续失败闭锁。
5. 当前完整夹具应得到 0 个 syntax error 和 0 个 semantic error；注入
   未登记操作的负向样例必须 RED；现有产品互动和 trigger 测试继续通过。

`VALIDATED` 仅说明上述 schema 切片通过，不代表夹具运行时成功。
